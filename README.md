# 求职管家独立版

这是一个不接入外部 Agent 的本地求职投递工作台。用户在网页工作台里填写自己的资料、简历、求职方向和投递条件，然后手动启动定量投递，或启动按时间窗持续运行的投递任务。

它不是聊天机器人，也不包含 QQ、微信、HR 对话或回复草稿功能。需要让其他 Agent 通过自然语言规划并调用投递工具，请使用配套的 [求职管家 MCP 版](https://github.com/Alxdzh/job-agent-mcp)。

## 这个版本能做什么

- **管理资料和简历**：在工作台保存个人资料、经历、求职方向、城市、薪资和简历版本。
- **连接招聘平台**：支持 BOSS 直聘、智联招聘、51job（前程无忧）和猎聘；每个平台单独启用、登录和配置。
- **可见浏览器投递**：使用系统原生 Chrome 的可见页面完成登录、搜索、选择城市、读取职位详情和投递；登录态保存在本机，后续可复用。
- **两种投递方式**：选择平台和数量执行“手动投递”；或者点击右上角按钮启动“不限数量”的持续投递。
- **节奏和时间窗**：批次数量、批次休息、岗位间隔使用随机范围；可以设置每天允许投递的开始和结束时间，并为每个平台独立冷却和轮换。
- **状态和记录**：查看当前阶段、平台、已扫描、成功、跳过、跳过原因、冷却状态、浏览器页面状态，以及本地投递记录。
- **JD 判断**：如果需要后台自动分析 JD 是否符合条件，在“设置”里填写用户自己的云端模型 API。模型只使用用户自己配置的接口，不内置 API Key。

默认不会因为启动程序、打开工作台或保存设置而投递；必须点击开始按钮并明确选择投递方式。默认使用可见浏览器。只有用户主动开启“静默模式”时才不把浏览器窗口带到前台；遇到登录、验证码、风控或异常页面时，需要用户查看可见页面并人工处理。

## 安装

### Windows 10/11：一键启动

1. 下载本仓库 ZIP 并解压到没有权限限制的目录。
2. 双击根目录的 `one-click-start.bat`。
3. 启动器会检查 Node.js 22.12+、系统 Google Chrome 和项目依赖；缺少 Node.js 或 Chrome 时会尝试使用 `winget` 安装。
4. 服务启动后会打开 `http://127.0.0.1:8788/`，并在桌面创建 `Job-Agent-Workbench` 快捷方式。

GitHub 源码仓库不提交 `node_modules`。第一次启动如果本机没有依赖，需要网络执行 npm 安装；启动器会设置 `PUPPETEER_SKIP_DOWNLOAD=1`，使用系统 Chrome，不额外下载 Chromium。没有 `winget` 时，请先手动安装 Node.js 22.12+ 和 Google Chrome，再重新运行启动器。

一键启动只负责启动服务，不会自动开始投递，也不会创建开机自启计划任务。若启动器报错，请按提示修复环境后再次运行；日志在 `daemon/log/daemon.log`。

### Windows 手动启动

在 PowerShell 中执行：

```powershell
Set-Location .\daemon
$env:PUPPETEER_SKIP_DOWNLOAD = "1"
npm install
node index.mjs
```

然后用浏览器打开 `http://127.0.0.1:8788/`。

### macOS / Linux

当前一键启动脚本是 Windows 版。macOS 和 Linux 需要先安装 Node.js 22.12+、Google Chrome，再在仓库根目录执行：

```bash
cd daemon
export PUPPETEER_SKIP_DOWNLOAD=1
npm install
node index.mjs
```

启动后打开 `http://127.0.0.1:8788/`。不同系统的 Chrome 安装位置和权限可能不同；如果程序无法找到 Chrome，请检查本机 Chrome 安装或按项目配置指定可执行文件。

## 第一次使用

1. 打开“资料”，填写姓名、联系方式、经历、目标方向、城市、薪资和简历正文，并保存。
2. 打开“设置”，填写自己的云端模型 API（需要 JD 自动判断时），设置平台搜索条件、投递时间窗和随机节奏。
3. 在平台登录区域逐个平台点击“打开登录”，在弹出的可见 Chrome 页面完成登录或扫码，再点击“检查”确认登录态已保存。
4. 在“手动投递”区域选择平台和数量，点击“开始本轮”；或者点击右上角“开始持续投递”，让任务在时间窗内按配置节奏运行。
5. 在状态卡片和“最近投递”中核对平台名称、岗位、结果和跳过原因。暂停会保留当前任务进度，恢复时继续剩余任务。
6. 遇到登录失效、验证码、风控、页面卡住或无法确认成功时，先暂停任务，处理可见浏览器页面后再继续。

## 运行规则

- 每个平台有独立的启用状态、登录态、关键词、城市和投递节奏。
- 一个平台注册冷却时，其他处于可投递状态的平台可以继续运行；不会因为某个平台休息而阻塞全部平台。
- 城市、关键词、筛选、详情和投递通过当前网页控件完成，不能用城市码或查询 URL 代替页面操作。
- 任务只记录实际确认到的结果；没有投成功不会显示成“已投”。
- `daemon/state`、`daemon/log` 以及当前用户目录中的配置和浏览器数据属于运行数据，不应提交到 GitHub。
- 停止投递和关闭后台服务是两件事：先在工作台暂停任务；不再使用时关闭运行窗口或按项目提供的退出后台操作，下次重新双击启动即可。

## 数据与隐私

本仓库是脱敏模板，不包含 API Key、个人资料、简历、历史投递记录、Cookies、浏览器登录态或本机数据库。首次运行时，配置和运行数据会写入当前用户目录及项目的 `daemon/state`、`daemon/log`；换电脑需要重新配置和登录。

不要把自己的 `daemon/state`、`daemon/log`、浏览器用户目录、`.env` 或配置密钥上传到公开仓库。发布给别人时，请使用没有运行数据的副本。
